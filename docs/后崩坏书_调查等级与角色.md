# 后崩坏书：调查等级 / 角色解锁（2026-10-28）

## 现象

进入后崩坏书（map 401 / DLC 系统）：

- 左上角「调查等级」是空的（没有 Lv.）
- 角色选择里一个角色都没有

服务端日志里，每次登录都固定三条未处理：

```
12:00:xx GetDLCReq not handled!
12:00:xx GetDLCTowerReq not handled!
12:00:xx GetDLCAvatarReq not handled!
```

## 协议与客户端字段

| 协议 | 用途 | 客户端处理 |
|---|---|---|
| 3550 `GetDLCReq` → 3551 `GetDLCRsp` | 调查等级 | `OnGetDLCRsp` `0x1827B44B0`：`this->KOLICAPONBH = rsp.level`（直接赋值，不按 exp 反算） |
| 3559 `GetDLCAvatarReq` → 3560 `GetDLCAvatarRsp` | 角色列表 | `OnGetDLCAvatarRsp` `0x1827B3AE0`：遍历 `avatar_list`，按 `avatar_id` 建 `DLCAvatarDataItem(id, avatar, level)` 存进字典 |
| 3574 `GetDLCTowerReq` → 3575 `GetDLCTowerRsp` | 后崩爬塔 | 未实现（与本次需求无关） |

角色解锁判定 `IsAvatarUnlock(avatarID)`（`0x1827B40B0`）只做一件事：

```c
dict = this->DMEDHLHDLGM;              // 上面那个字典
if (dict == NULL) return false;
return dict.ContainsKey(avatarID);
```

也就是说：**字典里有这个 id 就算解锁**，不需要额外的解锁字段。

## 表锚点

`DLCLevelData.json`（30 行，`level` 1..30）：

```json
{"level": 1, "exp": 400, "reward": 0, ...}
```

`exp` = 从本级升到下一级所需经验。满级 30。

`DLCAvatarData.json`（3 行）：

```json
{"DLCAvatarID": 1203, "index": 2, "UnlockHintStoryID": 0}
{"DLCAvatarID": 1304, "index": 3, "UnlockHintStoryID": 104014}
{"DLCAvatarID": 1411, "index": 1, "UnlockHintStoryID": 0}
```

`UnlockHintStoryID` 只用于界面提示，客户端实际解锁靠 avatar_list，所以三个全发。

## 四、角色天赋与技能等级（2026-10-28 补）

### 为什么之前是空的

天赋列表**只认服务端下发的 `talent_list`**，表只提供图标/名字/等级上限。反汇编链路：

```
DLCAvatarDataItem(avatarID, dlcAvatar, level)              0x180628100  构造，只存 proto
  └ GetTalentListByType(type)                              0x1806276A0  遍历 avatarSampleData+0x18
                                                          = DLCAvatar.talent_list（proto）
  └ GetTalentDataItem(talentID)                            0x1806273A0  在 talent_list 里按 id 找
        找不到 → 传 null
  └ OHHANBBFFIA(owner, talentID, protoTalent, 1)           0x181EA5E80  level = proto != null ? proto.level : 1
                                                          KINNKFHBBHL(上限) = GetTalentMaxLevel(talentID)
```

`GetDLCAvatarReqHandler` 之前只发 `avatar_id` + 空 `equip_talent_list`，`talent_list` 一条都没有，
所以天赋/技能界面空、等级自然是「没有」。

## 五、天赋词条（affix，2026-10-28 补）

### 机制

客户端套装档位（`0x180626CC0 GetApplicableAffixSetList` / `0x180626B50 GetAffixSuiteCount`）：

```
遍历 GetTalentListByType(4)（类型 4 = 武器/特技，每个角色 4 个）
  按 protoTalent.affix_set_id 分组计数
  count <= 1 → 0 档；2~3 件 → 1 档；4 件及以上 → 2 档（满）
```

`affix_set_id` 直接读 proto（getter `0x181EA3B10` 读 `DLCAvatarTalent + 0x18`）。
表 `DLCTalentAffixSet.json` 只有 5 个套装：

| AffixSetID | 效果 |
|---|---|
| 1 | HP 提升 |
| 2 | SP 提升 |
| 3 | 破盾（BuildUp） |
| 4 | 抗性 |
| 5 | 护甲 |

`DLCTalentAffix.json`（81 行）只是数值池，服务端不需要它——客户端按 setId 自己查。

### 改法

| 位置 | 改动 |
|---|---|
| 存档 `DlcAvatars.Talents[].AffixSetId / WaitAffixSetId` | 词条状态落库 |
| `DlcService.DefaultAffixSet` | 类型 4 新建时给 `dlc_affix_set`（缺省 1）→ 4 件同套装 = 满档 |

调参：`run\openworld.json` → `"dlc_affix_set": 1`（1~5，0 = 按 1）。

## 六、爬塔（无限塔，2026-10-28 补）

### 之前为什么是空的

登录必现 `GetDLCTowerReq not handled!`，客户端拿不到 MyTowerData，界面 0 层无赛季。

客户端 `DLCTowerData.Refresh(GetDLCTowerRsp)`（`0x18074DA80`）：

```
scheduleMetaData      = DLCTowerSchedule.Get(rsp.schedule_id)          ← 查不到就是 null
currentFloorMetaData  = DLCTowerFloor[(progress+1), schedule.ConfigType]
IsTowerFinished       = max_progress >= schedule.MaxFloor
CanTowerBattle        = progress < schedule.MaxFloor
CurrentFloor          = CanTowerBattle ? progress + 1 : progress
```

`progress` 就是「已通过层数」；`DLCTowerStageEndReq.progress` 客户端填的是 **CurrentFloor**（当前挑战层号，`0x181AB2C20` 第 123 行），所以通关后直接把它当新的已通过层数即可。

### 赛季选择

`DLCTowerSchedule.json` 454 行，按周排到 2035 年。当前时间（2026-10-28）正好落在：

```
ID 255 · 2026-10-26 04:00 ~ 2026-11-02 02:00 · ConfigType 1201 · MaxFloor 23 · LevelID 143404
```

`DLCTowerScheduleData.Current()` 按「StartTime ≤ now ≤ EndTime」动态取，跨周自动换季；
表全部过期时回落到 EndTime 最晚的一条，保证界面永远有内容。

`ConfigType` 必须和 `DLCTowerFloor` 的分组对上：1201 组正好 1~23 层。

### 已知限制

- 分数是估算（`1000 - 耗时`），不是真实战斗评分；
- 排行榜空（单机服务端没有他人数据）；
- CheckPoint 复活不回退层数（客户端自己处理 `IsCheckPoint`）。
