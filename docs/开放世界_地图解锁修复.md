# 开放世界「4 张图 · 1 锁 · 3 未激活」修复

日期：2026-10-28

## 一、现象

开放世界选择页 4 张卡：

| 卡片 | mapId |
|---|---|
| 樱色轮回 | 1 |
| 天命总部 | 2 |
| 后崩坏书 | 401 |
| 后崩坏书 第二章 | 601 |

天命总部显示锁图标，其余 3 张显示「未激活」；底部「权限激活」「进入」两个按钮都是灰的，
提示文案「地图解锁后，通关剧情第一章，即可解锁周期内容玩法」。

## 二、根因

`OpenworldMapStatus` 的取值顺序是

```
0 NONE          未激活
1 ACTIVATE      已激活
2 AUTO_ACTIVATE 可「权限激活」
3 LOCK          锁定
```

而服务端两处把它**写死成 3**：

| 位置 | 原代码 |
|---|---|
| `Server/Handlers/GetNewOpenworldReqHandler.cs` | `OpenworldMapBriefData.Status = 3u` |
| `Server/Handlers/GetOpenworldMapReqHandler.cs` | `GetOpenworldMapRsp.Status = 3u` |

写死 3 等于「永久锁定」，所以怎么点都进不去。

另外 **4504 `ActivateOpenworldMapReq`（页面底部「权限激活」按钮）服务端没有 handler**，
整份 `v2_Server.log` 里 0 次命中 —— 点了不回包，客户端只能等超时，按钮永远是灰的。

## 三、改动

### 1. 新增 `Server/GameServer/OwMapTuning.cs`

热读 `run/openworld.json`（改文件即生效，不用重启服务端），键：

| 键 | 默认 | 含义 |
|---|---|---|
| `map_status` | 1 | 下发的 `OpenworldMapStatus`；0 视为未配置 → 1；填 3 可复现原问题 |
| `extra_map_ids` | `[]` | 追加进 `map_list` 的 mapId（客户端表里有、存档没建行的图） |
| `next_refresh_seconds` | 259200 | 4497 的 `next_refresh_time` |
| `close_seconds` | 259200 | 4497 的 `close_time` |

默认文件：

```json
{
  "map_status": 1,
  "extra_map_ids": [],
  "next_refresh_seconds": 0,
  "close_seconds": 0
}
```

### 2. `GetNewOpenworldReqHandler`

- `Status` 改由 `OwMapTuning.Status` 给。
- 地图清单 = `session.Player.OpenWorlds` **+ `extra_map_ids`**。
  原来只发存档里已有的行（`ShowMapList` 过滤后只剩 1,2,301,401,601,701,801,1001），
  客户端表里有、存档没建行的图拿不到 status，按 0 = NONE 渲染，看起来就是「未激活」。
  追加行用 `OpenWorldCycleData.GetInitCycle(mapId)` 补 cycle。
- 日志改成 `[OW] GetNewOpenworld -> mapLists=1:1,2:1,...`（打印 mapId:status）。

### 3. `GetOpenworldMapReqHandler`

`GetOpenworldMapRsp.Status` 同样改由调参给。这条是真正「进入地图」时的响应，
状态没改的话即使列表显示已激活，进去也会被拒。

### 4. 新增 `Server/Handlers/ActivateOpenworldMapReqHandler.cs`

4504 → 4505，回 `Succ` + 回显 `map_id`。地图是否已激活由 4497/4498 的 `status` 决定，
不落库，所以不需要额外存档字段。

对照修复前：`mapLists=1,2,301,401,601,701,801,1001`（全部 status=3）。

## 五、表锚点

- `OpenWorldMap.json` 19 行：`MapId / MapType / UnlockLv / ShowTime / UnlockTime / MapNameText / MapSelectPath`
  - 4 张卡对应 `MapSelectPath`：PicMapOW01=1、PicMapOW02=2(+111~114,301~303)、PicMapOW03=401 等、PicMapOW04=601
- `OpenWorldCycleData.json` 14 行，给每个 mapId 初始 cycle：
  `1→2、2→11、401→41、501→51、601→61、701→71、801→81、1001→101`
- 别和 `WorldMap.json`（世界地图卡片，228 行，FT/GeneralActivity 那套）混淆，是两个系统。

## 七、天命总部锁定的真正原因：剧情门禁（2026-10-28 补）

`status` 改成 1/2 之后，樱色轮回能进了，但**天命总部（map 2）仍显示锁**。
它跟 status 无关，是客户端 `NewOpenWorldModule.IsMapUnlock(mapID)`（0x1828DDD10）另外三道门：

```
cfg = ExcelMeta.OpenWorldMap.Get(mapID)          // 这里读的是 OpenWorldMap.json 那一行
if (cfg != null) {
    if (TryGetTimeFromExcelString(cfg.UnlockTime, out t)
        && cfg.UnlockLv <= 玩家等级
        && IsStoryFinish(cfg.UnlockStoryId)) {    // ← 卡在这
        if (Now >= t) return true;
    }
}
return false;
```

`IsStoryFinish(storyID)`（0x1828DF070）：从 `allStoryDict` 里取该 story，读 `+0xA4` 状态字段是否 `== 2`（Finished）；找不到直接 false。

对照表：

| mapId | 名称 | UnlockLv | UnlockStoryId | 说明 |
|---|---|---|---|---|
| 1 | Sakura Samsara 樱色轮回 | 16 | 0 | 无剧情门禁 |
| 2 | Markas Schicksal 天命总部 | 50 | **308** | 樱色轮回 3-8，本次卡点 |
| 401 | Pasca Honkai 后崩坏书 | 30 | 0 | 无剧情门禁 |
| 601 | 后崩第二章 | 30 | 0 | 无剧情门禁 |

`storyId = StorySeriesID * 100 + StorySeriesStep`，所以 308 = series 3 step 8（`StoryMap=1`）。

而原来的 `GetOpenworldStoryReqHandler` 发的是：

```csharp
FinishStoryIdLists = 存档里 IsDone 的（空数组）
CurStoryLists      = 存档里未完成的
IsAll              = true
```

客户端 `CreateOrUpDateAllStories`（0x1828CC230）在全量分支里：
- `cur_story_list` 每条 → `new KFOBMMKEFFA(story, 1)`（进行中）
- `finish_story_id_list` 每条 → `new KFOBMMKEFFA(storyId, 2)`（已完成）

finish 是空的 → 所有 story 状态都是 1 → `IsStoryFinish(308) == false` → 天命永远锁。

### 改法

`run\openworld.json` 新增开关（热读，缺省 true）：

```json
"all_story_done": true
```

`GetOpenworldStoryReqHandler` 在全通模式下直接把整张 `OpenWorldStoryData.json`（1337 条 `StoryID`）
作为 `finish_story_id_list` 全量下发，`cur_story_list` 留空，并把存档 `User.OpenWorldStory`
补成 1337 条 `IsDone=true`（避免接取/领奖/进度上报读存档时又变成「没做过」）。

日志：

```
[OW] 读取 openworld.json -> map_status=2(生效 2) extra=[] nextRefresh=259200 close=259200 allStoryDone=True
[OW] GetOpenworldStory -> all done, finish=1337
[OW] GetNewOpenworld -> mapLists=1:2,2:2,301:2,401:2,601:2,701:2,801:2,1001:2
```

### 想只解锁天命、不想全通

把 `all_story_done` 改回 `false`，改成入库一批最小剧情集合。最小一条就是 308 本身：

```python
ids = [101, 102, 103, 104, 105, 106, 107, 108,      # series 1 樱色轮回 1-1..1-8
       201, 202, 203, 204, 205, 206, 207, 208,      # series 2
       301, 302, 303, 304, 305, 306, 307, 308]      # series 3，末条即 UnlockStoryId
```

（`storyId = series * 100 + step`，只放 308 也能解锁，放整段是为了剧情列表看起来连贯。）

改完不用重启服务端（`openworld.json` 是热读），重开客户端即可。
