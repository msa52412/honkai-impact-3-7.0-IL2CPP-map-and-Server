# 怪物具体数据需要服务端指定吗？

> 只读勘察。数据源：`LeServer\Common.dll`（服务端程序集）、`LeServer\Resources\ExcelOutputAsset\`、`PemukulPaku.dll`。
> 未修改任何文件。

---

## 结论

**默认不需要。** 单人战斗（主线 / 编年史 / 深渊 / 记忆战场 / 超弦空间）的怪物数值由**客户端本地模拟**，服务端只接收结算结果。
**唯一例外**：多人协作 / 阵营对抗玩法（大规模战争 MassiveWar、SLG 国战等）会由服务端同步共享 BOSS 血量。

---

## 一、服务端只加载了 1 张怪物表

服务端实际加载的是 `Common.dll` 内 84 个 `*Excel` 类。其中**怪物相关只有 1 个**：

| 加载类 | 对应文件 | 用途 |
|---|---|---|
| `ExBossMonsterDataExcel` | `ExBossMonsterData.json` | 记忆战场 BOSS 列表 / 分数 / 展示 |

资源目录里另有 **80+ 张怪物表**，服务端**一张都不加载**（纯客户端）：

```
MonsterConfigData      UniqueMonsterData      EditorMonsterPrototype
EditorMonsterActivityList  EditorUniqueMonsterData   MonsterResistance
StageDetail_Monster    StageDetail_Monster_Resist    OWEndlessMonsterData
QTEndlessMonsterData   MassiveWarMonsterData  CollectionMonsterData
MonsterCard*           PlatformShooterMonster RanchMonster* ...
```

> 关键：`MonsterConfigData`（怪物基础数值）、`UniqueMonsterData`（唯一怪）这些**战斗数值表根本不在服务端的加载清单里**。

---

## 二、战斗结果由客户端上报

协议里存在 `CmdStageBeginReq/Rsp`、`CmdStageEndReq/Rsp` 与 `StageEndReqBody`，字段全部是**客户端 → 服务端**的战斗结果：

| 字段 | 含义 |
|---|---|
| `monster_damage_list` / `self_monster_damage_list` | 怪物伤害列表 |
| `monster_kill_info` / `kill_monster_guid_list` / `killed_monster_list` | 击杀信息 |
| `monster_snapshot` / `monster_info_list` | 怪物快照 |
| `monster_hard_level` / `monster_level` / `monster_id` / `monster_group_id` | 怪物等级/ID |
| `battle_cost_time` / `stage_pass_time` / `battle_end_status` | 耗时/结束状态 |
| `stage_score` / `battle_score` / `battle_result` | 分数/结果 |

即：**客户端算完，服务端收结果**。服务端不向客户端下发怪物血量/攻击。

`ExBossMonsterData` 里虽有 `MonsterHp`，但同表字段 `BossPrefabPath`（`Entities/Monster/Boss/...`）、`ImagePath` 都是**客户端资源路径**，说明它主要服务于展示与分数（`MonsterBaseScore`），不是战斗数值来源。

---

## 三、例外：多人共享 BOSS 血量由服务端同步

`Common.dll` 中存在这些字段（同一协议块）：

```
server_set_lhs_boss_hp      server_set_rhs_boss_hp
client_set_left_hp          client_add_damage / client_total_damage
lhs_member_list / rhs_member_list
lhs_final_kill_player_uid / rhs_final_kill_player_uid
left_total_score / right_total_score / left_win_times
create_entity_list / update_cell / wait_select_path
```

这是**左右两侧共享同一个 BOSS、需要跨玩家同步血量与分数**的玩法，对应 `MassiveWar*`（`MassiveWarStage` 含 `DamageNeedRatio`、`MonsterWaveList`、`BossIdList`）/ SLG / 国战类。此类模式服务端必须知道并下发 BOSS 血量。

---

## 四、另外两个相关机制

| 机制 | 说明 |
|---|---|
| `FightServerIp` / `FightServerPort` | 独立"战斗服"概念（联机用）。本私服 `config.json` 只有 GameServer 16100 + HTTP 8081/443，未配战斗服。 |
| `AntiCheatStageCheckConfig` | 服务端**内置**的反作弊关卡校验开关；`ExcelOutputAsset` 里**没有**对应表，不靠 Excel 配置。 |

## 五、实践建议

| 想改什么 | 改哪里 |
|---|---|
| 怪物血量 / 攻击 / 等级 / AI / 出场波次 | **客户端**（关卡 lua + 怪物配置，在客户端资源包内）——服务端不用动 |
| 掉落 / 奖励 / 挑战条件 / 开放条件 | **服务端** `ExcelOutputAsset\*.json` |
| 记忆战场 BOSS 轮换 / 分数线 | **服务端** `ExBossMonsterData.json`、`ExBossConfig.json`、`ExBossMonsterSchedule.json` |
| 超弦空间楼层 / 站点 / 段位 | **服务端** `UltraEndlessFloor.json`、`UltraEndlessSite.json`、`UltraEndlessGroup.json` |

> 注意：`StageData_Main.json` 里的 `KCFLLDNFHNN` 字段是**关卡 lua 脚本路径**（如 `Lua/Levels/Event2.2/3.0ExBossTrialEvent01.lua`），怪物生成逻辑在该 lua 里，由客户端执行。
