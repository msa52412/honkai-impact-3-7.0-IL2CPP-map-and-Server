# 崩坏3 7.0 三深渊 · 服务端架构与参数填入位置

> 适用范围：`D:\BH3\7.0\server-v2`（PemukulPaku v2）。
> 三个模式：**迪拉克之海**（Openworld, type=2）、**量子奇点**（Quantum, type=3）、**超弦空间**（Ultra, type=4）。
> 客户端二进制/资源不可改，本文所有服务端侧改动都落在 **协议字段 + Excel 表查询 + 运行时状态** 三处。

---

## 0. 一句话结论

| 模式 | 协议包段 | 服务端"配置中心" | 模式身份从哪来 | 天气/BOSS 从哪来 |
|---|---|---|---|---|
| 迪拉克之海 | 34xx（旧深渊全套） | `run\abyss_ow.json` → `OwTuning` | `3419` 请求体 `type`（空则 2） | `battle_config_id` → `OWEndlessBattleConfig` 的 4 区域 + 4 BOSS 区 + 4 天气 ID |
| 量子奇点 | 34xx（**同一个** 3419 响应 + `quantum_endless` 块） | 同上，另加 `qt_battle_config_id` | `3419` 请求体 `type=3` | 同上，但只认 `AreaScoreConfigID = 2000+能级(1..8)` 的 type=3 行 |
| 超弦空间 | 52xx（独立包段） | `run\ultra_endless.json` → `UltraTuning` | `5203` 请求（无 type，固定 Ultra） | **site_id 的附属属性**：组号 → `UltraEndlessSite` 的 4 个站点，天气/BOSS 由客户端按 site 查表 |

**最重要的一句**：迪拉克/量子的"参数"是**服务端可自由组合**的四元组（地图、BOSS、天气、能级）；超弦的天气/BOSS **不能脱离 site_id 单独填**，只能整组换 `site_groups`。

## 1. 请求链路

### 1.1 共用入口（三个模式都会走）

```
登录
 └─ 3432/3433 GetEndlessStatus       ← 决定「挑战」面板主推哪套、排期时间、其它深渊卡片
 └─ 3462/3463 EndlessSelectType      ← 客户端切模式，服务端同步 AbyssConfig
```

- `GetEndlessStatusReqHandler`（3432）：下发
  - `CurStatus.EndlessType  = AbyssConfig.CurStatusType`
  - `SelectedEndlessType    = AbyssConfig.SelectedEndlessType`
  - `NextStatusLists[]`    = 其它深渊（`AbyssConfig.OtherEndless`，`GroupLevel` 必须用 `OwGroupLevel`）
  - `BeginTime/EndTime/CloseTime = OwTuning.Period(...)`
- `EndlessSelectTypeReqHandler`（3462）：把客户端选的 `EndlessType` 映射成 1..6，调用 `AbyssConfig.SetSelected()`，保证 `SelectedEndlessType` 与 `CurStatusType` 不打架。

> 观测点：`[Abyss] GetEndlessStatus -> SelectedEndlessType=2 CurStatus.EndlessType=2 OwGroupLevel=21`

### 1.2 迪拉克 / 量子（旧深渊，34xx）

```
3432 GetEndlessStatus
  └─ 3419 GetOpenworldEndlessDataReq(type)
       └─ 3420 GetOpenworldEndlessDataRsp   ← 唯一的数据总入口（地图/天气/BOSS/段位/扰动/名单/进度）
            ├─ 进关：4462 OpenworldStageBegin → 3426 GetOpenworldEndlessStageInnerData
            ├─ 战斗：3438 BattleBegin → 3424 FinishMonsterGroup(3425) → 3434 ReportData
            ├─ 分数通知：3445 OpenworldEndlessPlayerUpdateNotify（OwTuning.push_score_notify）
            └─ 排行：3446 GetOpenworldEndlessTopGroup
```

- 3420 是**迪拉克和量子共用的同一个消息**，靠 `rsp.type` 区分：
  - `type=2` → 迪拉克
  - `type=3` → 量子，**额外**填 `rsp.quantum_endless { cur_monster_group, monster_progress, finish_monster_num }`
- `type==0` 的请求按 2 处理（`GetOpenworldEndlessDataReqHandler` 开头）。

### 1.3 超弦空间（52xx）

```
3432 GetEndlessStatus（SelectedEndlessType=4 时入口才亮）
  └─ 5202 GetMainData → 5203 GetMainDataRsp   ← 地图 4 槽 / 站点列表 / 段位 / 杯数 / 扰动 / 排行 / 分数
       ├─ 5211 EnterSite → 5212（只回显 site_id）
       ├─ 5206 ReportSiteFloor → 5207（每层最高分，落盘）
       └─ 5200 GetTopRank → 5201（当前为 stub：IsFeatureClosed=true）
```

- 超弦**不复用** 3419，也不看 `rsp.type`；`GetEndlessStatus` 只是入口开关。
- `5203` 崩溃过一次（5203 客户端 `Invalid wire-type`），根因不在业务数据，而在
  `PlayerFriendBriefData` 字段号错位（16..19），已按客户端真实布局修正：
  `16=frame_id / 17=mp_level / 18=custom_head_id / 19=on_medal`。

## 2. 共用层（三模式共享）

| 共用件 | 位置 | 作用 |
|---|---|---|
| `AbyssConfig` | `Server\GameServer\AbyssConfig.cs` | 进程内开关：`SelectedEndlessType` / `CurStatusType` / `OwGroupLevel` / `ShowOtherEndless` / `OtherEndless` / `SetSelected()` |
| `OwTuning` | `Server\GameServer\OwTuning.cs` | 旧深渊全部可调参数（`run\abyss_ow.json`，mtime 热加载） |
| `OwTuning.Period()` | 同上 | 三处时间窗统一出口：3433 / 3420 / 5203 都从这取 |
| `PlayerFriendBriefData` + 假名单 | 两个主 handler 各自组装 | 客户端排名/分组界面**没有 brief 就退化**成裸 uid；必须给每个 uid 配一条 brief |
| `GetEndlessStatus` / `EndlessSelectType` | `Server\Handlers\` | 入口选型；两者字段必须自洽，否则面板点进去是空页 |
| 运行时状态 | `run\data\abyss_state.json`、`run\data\ultra_endless_state.json` | 内存 + 落盘，不进 SQLite schema，不动 v1 存档 |
| 观测日志 | `_launch\logs\v2_Server.log` | `[Abyss]` / `[Ultra]` 两族日志是唯一可靠核对手段（客户端查表失败是静默的） |

### 2.1 为什么 brief 是共用难点

- 旧深渊：`MonoOWEndlessAvatarLayout` 按 `endless_data_list` 排序铺升降级区，每行用 `GroupInfo.GetNickName(uid)` 去 `brief_data_list` 找昵称。
- 超弦：`MonoUltraEndlessRankRowCmpt.SetupView` 用 `GetFriendBriefData(uid)`，查不到就空串 + 默认头像。
- 所以：**名单里出现的每个 uid 都必须有 brief**，否则界面"能开但像坏了"。
- 旧深渊提供 `brief_mask`（位掩码）和 `brief_self_only` 两个二分开关，专门用于定位"brief 里哪个字段让客户端静默拒绝整份响应"。

### 2.2 共用坑：`User.AbyssGroupLevel` 是超弦的，不是旧深渊的

- `User.AbyssGroupLevel` 是 1..9 的**杯数段位**（超弦 `UltraEndlessGroup`）。
- 旧深渊的 `GroupLevel` 是 11..35 的**分组等级**（`OWEndlessGroup`），两者不是一个域。
- 旧深渊若误用 1..9（例如建号默认 8），客户端 `RefreshPlayerGroup+0x404` 查 `GetOWEndlessGroupMetaByKey(8)` 得 null → NRE → 黑屏 + 每秒上百次 3419 请求风暴。
- 所以旧深渊单独走 `AbyssConfig.OwGroupLevel` / `OwTuning.GroupLevel`，绝不碰 `User.AbyssGroupLevel`。

## 3. 模式独立层

### 3.1 迪拉克之海（type=2）

**响应组装**：`GetOpenworldEndlessDataReqHandler`（3419→3420）

核心字段与来源：

| 字段 | 来源 |
|---|---|
| `Type` | 请求 `type`，0 → 2 |
| `GroupId` | 常量 `1` |
| `GroupLevel` | `OwEndlessConfig.ResolveGroup(type, OwTuning.GroupLevel)` → 夹进白名单后查 `OWEndlessGroup` |
| `CurTopGroupLevel` | 同阶梯最高档；`cur_top_group_level` 覆盖时也要夹白名单 |
| `HardLevel` | `OwEndlessConfig.EffectiveHardLevel()`（`abyss_ow.json.hard_level` 优先，否则表 `GroupHardLevel`） |
| `BossExtraScore` | `OWEndlessGroup.ExtraScore` |
| `TopGroupPlayerNum` / `TopGroupPromoteUnlockPlayerNum` | `OwTuning` 覆盖或表 `MaxCapacity` / `PromoteRank` |
| `BattleConfigId` | `OwEndlessConfig.ResolveRequestedBattleConfigId(type, battleHard)` |
| `BeginTime/EndTime/CloseTime` | `OwTuning.Period()` |
| `EndlessDataLists` / `BriefDataLists` | `roster_size` 条假名单，自己固定第 5 名，`selfScore = state.Score`（打过）或 20000-(rank-1)*500 |
| `MonsterGroupLists` | `OwEndlessState.BuildGroupList(...)`：**全量铺开**，已完成项 `progress=10000` |
| `FinishMonsterGroupLists` | `state.FinishedGroups`（客户端其实只认前者的 progress>9999） |

**地图/天气/BOSS 的落点**：

```
abyss_ow.json.battle_config_id
   → OWEndlessBattleConfig[62136]
        AreaIDList        = 3011,3012,3014,3013    // 地图 4 个区域
        BossAreaIDList    = 3015..3018             // 每层 BOSS 区
        EnvironmentIDList = 112,111,113,115        // 4 个区域各自的天气 ID
        AreaScoreConfigID = 1006                   // 场次顺序 + 计分组
   → OWEndlessAreaScoreConfig[1006]
        MonsterScoreConfig = 每层小怪计分组
        BossScoreConfig    = 每层 BOSS 计分组（131/132/133/134）
        SplitBattles       = 客户端推进顺序（BOSS 场用 3605 之类占位）
```

- **天气按区域逐个取值**：4 个区域 = 4 个独立天气，BOSS 区复用区域 4 的天气。
- **扰动只缩放怪物属性**（`NPCLevelLogic` group 0：199 → 血量 ×59.62 / 攻击 ×53.98），它不选地图、不选天气。
- BOSS 有两个 id：`SplitBattles` 里的占位 id 只管场次顺序；客户端 3424 上报的是 `BossScoreConfig[layer]`（如 131）。服务端凡按层处理 BOSS 都必须换成后者（`OwEndlessConfig.BossGroupOf / ReportedGroupId`）。

### 3.2 量子奇点（type=3）

与迪拉克**同一条 3419 链路**，差异只有四点：

1. **战斗配置必须属于 type=3**
   - `OwTuning.QtBattleConfigId`（当前 `100033`）只在 `OWEndlessBattleConfig.EndlessConfigType == 3` 时才采用；
   - 否则自动挑选：`AreaScoreConfigID = 2000 + clamp(能级,1,8)`，同档取最小 `BattleConfigID`（`OwEndlessConfig.PickQuantum`）。
   - 历史事故：把 62136（type=2）塞给量子 → 客户端 `ByKey(62136,3)` 查空 → `QTInLevelData.Refresh` 的 `battleConfig/areaScoreConfig` 全 null → 准备页与进关链路直接断。
2. **能级夹紧**：界面 `HardLevel` 可以下发 199，但**选盘**必须用 `BattleHardLevel()` 夹到 ≤8（客户端只认 2001..2008）。
3. **额外响应块** `quantum_endless`：`cur_monster_group = state.CurGroupId`、`monster_progress = state.MonsterProgress`、`finish_monster_num`。固定 0 会把客户端每次都按回第一场。
4. **白名单不同**：量子 `{11..14, 21..24, 31..35}`；迪拉克 `{21..24, 31..34}`。

### 3.3 超弦空间（type=4）

**响应组装**：`UltraEndlessGetMainDataReqHandler`（5202→5203）

| 字段 | 来源 |
|---|---|
| `ScheduleId` | `UltraEndlessState.EffectiveScheduleId`（`ultra_endless.json.schedule_id`，0 → 1028，>65535 拒绝） |
| `GroupLevel` | `User.AbyssGroupLevel`（或 `group_level` 覆盖）→ `UltraEndlessGroup.ByLevel/ClampLevel`；非法值兜底 8（红莲），并回写存档 |
| `TopGroupLevel` | `UltraEndlessGroup.MaxGroupLevel` |
| `CupNum` | `UltraEndlessGroup.CupNumOf(groupLevel)`（必须与段位同档） |
| `MainData.SiteLists` | `UltraEndlessSite.All` 里 `SiteId/10 ∈ site_groups` 的站点，每个站点再按 `StageId` 查 `UltraEndlessFloor` 铺 `floor_list` |
| `floor_list[].max_score` | `UltraEndlessState.FloorScore(siteId, floorId)`（5206 记的历史最高分） |
| `DynamicHardLevel` | `UltraTuning.DynamicHardLevel ?? User.AbyssDynamicHard` |
| `EndlessPlayerLists` / `BriefDataLists` | 10 个假玩家 + 自己，按客户端 `ComparePlayer` 规则排序；分数来自 `state.MaxStageScore` |
| `MainData.EndTime/CloseTime` | 当前写死 now+7d / +1200s（**未接 `OwTuning.Period`**） |

**关键：site 的两条渲染路径**

- `MonoUltraEndlessZoneMapCmpt.SetupSites`：地图 4 个 Area 槽，每个槽按节点名 `GetSiteIDByNodeName("AreaN")` 反查 `site_list`，**严格 first-match** → 地图永远显示 `site_list` 里最前那一组。
- `MonoUltraEndlessZoneMapCmpt.SetupScrollerSites`：按 `site_list` 下标全部渲染 → 滚动列表显示所有组。
- 结论：`site_groups` 只写一个组号最省事；写多个组时地图只认第一组。

**超弦的天气/BOSS 由 site_id 决定，不由服务端字段决定**

- 服务端只下发 `site_id`；客户端用 `UltraEndlessSite[site_id]` 的 `BuffID` / `StageID` 去查天气和 BOSS。
- 所以"换天气"= 换组号，不能像迪拉克那样只改 `EnvironmentIDList` 的某一格。
- 176 组的对照见 `超弦空间_天气boss表.md`。

## 4. 参数填入位置总表（**核心**）

> 填参有三条通道：
> **A. 热加载 JSON**（推荐；改文件即生效，按 mtime 重载）
> **B. 聊天命令**（进程内静态，重启失效）
> **C. Excel 表 / 代码常量**（需重启，改错会崩客户端，见 §4.5）

### 4.1 旧深渊（迪拉克 / 量子）——`run\abyss_ow.json`

读取点：`OwTuning.Load()`（`Server\GameServer\OwTuning.cs`）
生效点：`GetOpenworldEndlessDataReqHandler` + `OwEndlessConfig` + `GetEndlessStatusReqHandler` + `GetOpenworldEndlessTopGroupReqHandler`

| 想改什么 | JSON 键 | 代码读取 | 最终响应字段 | 客户端表现 |
|---|---|---|---|---|
| 分组等级（段位） | `group_level` | `OwTuning.GroupLevel` → `OwEndlessConfig.ResolveGroup()` | `3420.GroupLevel` | 原罪/禁忌/苦痛/红莲/无限 |
| 当前最高档 | `cur_top_group_level` | `OwTuning.CurTopGroupLevel`（夹白名单） | `3420.CurTopGroupLevel` | 顶层标识与晋级说明 |
| 扰动幅度 | `hard_level` | `OwTuning.HardLevel` → `EffectiveHardLevel()` | `3420.HardLevel` | 界面"能级/扰动"数字 |
| 分组容量 | `top_group_player_num` | `OwTuning.TopGroupPlayerNum` | `3420.TopGroupPlayerNum` | 名单人数上限 |
| 晋级名次 | `promote_unlock_num` | `OwTuning.PromoteUnlockNum` | `3420.TopGroupPromoteUnlockPlayerNum` | 升降级分割线 |
| 地图+天气+BOSS | `battle_config_id` | `OwTuning.BattleConfigId` → `ResolveRequestedBattleConfigId()` | `3420.BattleConfigId` | 4 区域图 / 4 天气 / 4 BOSS |
| 量子专用战斗配置 | `qt_battle_config_id` | `OwTuning.QtBattleConfigId`（仅 type=3 且表里 Type=3 时采用） | 同上 | 量子地图与天气 |
| 假名单条数 | `roster_size` | `OwTuning.RosterSize`（0→20，>50 夹到 50） | `EndlessDataLists.Count` | 分组页人数、名次 |
| 是否下发 brief | `send_brief` | `OwTuning.SendBrief` | `BriefDataLists` | 关掉后昵称变裸 uid |
| brief 字段掩码 | `brief_mask` | `OwTuning.BriefMask`（1 昵称/2 等级/4 头像/8 头框/16 头像框/32 mp/64 在线） | `PlayerFriendBriefData` 各字段 | 二分定位客户端拒绝点 |
| 只发自己的 brief | `brief_self_only` | `OwTuning.BriefSelfOnly` | 同上 | 同上 |
| 周期起止 | `period_fixed` / `period_begin_time` / `period_end_time` | `OwTuning.Period()` | 3433 与 3420 的 `Begin/End/Close` | 排期页日期（0 会显示 1970） |

| 结算宽限 | `period_close_delay` | 同上 | `CloseTime` | 关闭倒计时 |
| 打完后推分数 | `push_score_notify` | `OwTuning.PushScoreNotify` | 3445 notify | 打完不刷新分数时关/开它 |

### 4.2 超弦空间——`run\ultra_endless.json`

读取点：`UltraTuning.Load()`（mtime 热加载）
生效点：`UltraEndlessGetMainDataReqHandler` / `UltraEndlessState`

| 想改什么 | JSON 键 | 代码读取 | 最终响应字段 | 客户端表现 |
|---|---|---|---|---|
| 场景组（地图+天气+BOSS） | `site_groups`（组号 = `SiteID/10`） | `UltraTuning.SiteGroups` → `ActiveSiteGroups()` | `5203.MainData.SiteLists` | 地图 4 槽 + 滚动列表 |

| 扰动 | `dynamic_hard_level` | `UltraTuning.DynamicHardLevel ?? User.AbyssDynamicHard` | `5203.DynamicHardLevel` | 关卡难度系数 |

{ "site_groups": [165], "schedule_id": 0, "group_level": 0, "dynamic_hard_level": null }
```

已实测生效（`v2_Server.log`）：

```
[Ultra] 读取 ultra_endless.json -> site_groups=165 ...
[Ultra] 5203 GetMainData: schedule=1028 ... groups=[165] sites=4 -> 1651(5f/0p) 1652(5f/0p) 1653(2f/0p) 1654(5f/0p)

### 4.3 入口选型——`AbyssConfig`（进程内静态）

| 字段 | 默认 | 聊天命令 | 作用 |
|---|---|---|---|
| `SelectedEndlessType` | `2` | `abyss legacy <1..6>` | 面板主推哪套：1 普通 / 2 迪拉克 / 3 量子 / 4 超弦 / 5 贪婪 / 6 前哨 |
| `CurStatusType` | `Openworld(2)` | 随 `SetSelected()` 联动 | 必须与 Selected 自洽 |
| `OwGroupLevel` | `21` | `abyss owlevel <11..35>` | 仅用于 `NextStatusLists[].GroupLevel` |
| `ShowOtherEndless` | `true` | `abyss next 0/1` | 是否挂其它深渊卡片 |

> 注意：`OwGroupLevel` 目前只是"其它深渊卡片"的展示档位；真正 3419 的 `GroupLevel` 走 `OwTuning.GroupLevel`（=34），两者可以不同，但都应落在白名单内。

其它命令：

- `abyss temp <n>` / `abyss d <n>`：写 `User.AbyssDynamicHard`（超弦扰动兜底）
- `abyss bracket <1..9>`：写 `User.AbyssGroupLevel`（超弦段位）
- `abyss lock 0/1/2`：高级区/终极区锁定
- `abyss owinfo`：打印 `OWEndlessGroup` 全部档位 + 扰动 + 容量 + 晋级名次

### 4.4 运行时状态文件（不是配置，但会覆盖显示）

| 文件 | 写入点 | 影响 |
|---|---|---|
| `run\data\abyss_state.json` | `OwEndlessState.Persist()`（3424 推进 / 3426 / 3420 Align） | 旧深渊分数、当前组、组内进度、已完成组 |
| `run\data\ultra_endless_state.json` | `UltraEndlessState.Persist()`（5206 刷新纪录时） | 超弦每层最高分 → 5203 `floor_list[].max_score` |

### 4.5 Excel 表 / 代码常量（通道 C，谨慎）

## 5. 三份配置表怎么用（口径）

### 5.1 `owendless_configs.csv`（595 条旧深渊全量）

一行 = 一个 `battle_config_id`，字段直接对应客户端查表结果：

```
battle_config_id, score_config, map, order_code,
area1..4, env1..4, env_name1..4, boss1..4, env_cn1..4,
env_buff1..4, env_effect1..4, boss_name1..4
```

用法：

1. 先按 `score_config`（= `AreaScoreConfigID`）和 `type` 筛；
2. 看 `env1..4` 是否是想要的 4 个天气（**逐区域独立**，BOSS 复用区域 4）；
3. 把 `battle_config_id` 填进 `abyss_ow.json.battle_config_id`（迪拉克）或 `qt_battle_config_id`（量子，必须是 type=3 行）；
4. 服务端日志 `[Abyss] 地图 ... areas=... env=...` 核对。

> `order_code` / `map` 是人工备注列，服务端不读。

### 5.2 `量子奇点_配置表.md`（299 条 type=3）

- 每行 = `OWEndlessBattleConfig.EndlessConfigType=3` 的一个配置。
- 天气/BOSS **只取第一层（layerId=0）** 的口径，因为量子主玩法是单层循环。
- `配置ID` 可直接填 `qt_battle_config_id`；若留 0，服务端按 `AreaScoreConfigID=2000+能级` 自动挑。
- 表里标注"BOSS 层是否卡死"的是客户端战斗侧问题，服务端改不了。

### 5.3 `超弦空间_天气boss表.md`（176 组）

- 一行 = 一个**组号**，第三列 4 个 `site_id` 是这一组要下发的全部站点。
- 服务端只填 `site_groups`（组号，不是 site_id）。
- 140 组能凑齐 4 个场景；36 组不足 4 个 → 地图会有槽被隐藏（正常现象）。
- 地图 4 槽只认 `site_list` 第一组，滚动列表认全部。

## 9. 道具系统（迪拉克 / 量子，3421 / 3422 / 3427）

### 9.1 一句话

背包在**服务端**：3420 下发 `item_list`，3422 扣库存 + 回 `effect_item_list`，**用完必须补推一包 3421**，陷阱走 3427 的 `battle_list[].trap_list`。

### 9.2 客户端口径（反汇编实证，UserAssembly.dll 7.0）

| 地址 | 函数 | 行为 |
|---|---|---|
| `0x18189BD50` | `RefreshMyItemList` | 清空 `_itemList(+0x80)`，**只保留 `num != 0`** 的项 |
| `0x18189BB30` | `RefreshEffectItemList` | 清空 `_effectItemList(+0x88)`，按每项 `num` 次重复加入 `item_id` |
| `0x18189B7F0` | `OnUseOpenworldEndlessItemRsp` | `retcode==0` 只调 `RefreshEffectItemList(rsp.effect_item_list)`，**不动背包** |
| `0x18189AC70` | `OnOpenworldEndlessItemUpdateNotify` | 用 `notify.item_list` 调 `RefreshMyItemList` → **3421 是背包唯一刷新通道** |
| `0x18189A980` | `OnGetOpenworldEndlessInnerDataRsp` | 只做 `RefreshTrapList` / `RefreshEffectItemListByInnerDataRsp` / `RefreshSceneGearDict` |
| `0x18189C940` | `RefreshTrapList` | 从 3427 `battle_list[].trap_list` 重建 `_trapList(+0x78)` |
| `0x1819C49B0` | `CheckItemEffectOverMaxAmount` | 同 type 的 effect 条目数 ≥ `OWEndlessItemEffect.effectAmount` 就判满；**type=3 时改查 `RelateBuff` 的 type=6（effectAmount=1）** |
| `0x181AD4F60` | `RequestUseOpenworldEndlessItemReq` | proto 里只有 `item_id / target_uid / invasion / item_num`，**battle_id 字段根本不存在**，第 4 个参数被直接丢弃 |
| `0x1814EB040` | 关卡内道具栏（`RefreshTrapView` 那一套） | `GetCurrentBattleID()` → 带着 battleID 调 3422；判满就弹 `GeneralDialog`，不再发包 |
| `0x1814ED000` | 总览图快捷使用 | 非入侵类道具直接发 3422，`target_uid=0 / battleID=0` |
| `0x1819C5A60` | `GetOWEndlessItemTable(battleID)` | 只遍历 `_trapList`，按 `trap.battle_id == battleID` 拼 Lua 表（地图/关卡内陷阱图标的唯一来源） |

推论：
- 3420 的 `effect_item_list` 在主界面不会被应用，填了也不出错，留着让切页状态一致。
- 3422 成功后不补 3421，客户端道具栏数量就不会变（这是最容易漏的一步）。
- 陷阱落点由服务端定，`rsp.battle_id` 只是回给客户端做提示。**关卡内用法拿不到 battleID，只能靠 3438 记下来的 `LastBattleId`。**
- 陷阱的「技能/图标」就是 `RelateBuff`（type=6）进 `effect_item_list`：道具描述写的是 Heal Self（停流血 + 每秒 3% HP / 3 SP，10 秒）。不写就只有背包数字变化，没有 buff 图标、技能不生效。
- 效果不能永久留在列表里：`effectAmount` 是「同类同时存在几个」，永久留着会让客户端第二次点同类道具就弹「已达上限」而根本不发包。服务端用 60 秒 TTL 近似 CD。

### 9.4 每种 type 的语义（表实测）

| type | 道具 ID | 含义 | 服务端行为 |
|---|---|---|---|
| 1 | 150010 | 干扰器（`maxUseRange=minUseRange=3`） | 扣库存回 Succ，`new_invasion_id=0`（私服无 PVP，客户端见此不进入侵流程） |
| 2 | 150001..150009 | 药水（物理/元素伤害、SP 回复，S/M/L） | 扣库存 → 写 `effect_item_list`，同 type 替换（`effectAmount=1`） |
| 3 | 150021..150028 | 陷阱（`RelateBuff` → 150031..150038） | 扣库存 → 落点见 9.4.1；**RelateBuff 同时进 effect_item_list**（技能/图标） |
| 4 | 150040 | 净化 | 同 type 2，`effectAmount=3` |
| 5 | 150020 | 钥匙 | 同 type 2，`effectAmount=1` |
| 6 | 150031..150038 | 陷阱效果项 | **不进背包**，只作为陷阱的关联 effect 出现 |

#### 9.4.1 陷阱落点（三档）

1. `LastBattleId != 0`（正在打某场，3438 记的）→ 直接落这场，`rsp.battle_id` 回它；
2. 否则 `LastAreaId != 0`（刚进过某张图）→ 落这张图第一个还有空位的 battle；
3. 都没有（刚重启、在总览图上点道具）→ 先记 `BattleId=0` 的「悬空陷阱」，等下一次 3427 进区域时落到该区域的空位里（`AssignPendingTraps`）。

空位上限取 `OWEndlessBattleArea.trapMaxNum`（普通区 2~3，BOSS 区 0）。

初始库存（`OwEndlessItemState.SeedAmount`）：干扰器 3 / 药水各 3 / 陷阱各 3 / 净化 2 / 钥匙 1。
想改就改 `run\data\abyss_items.json`（结构 `{ "uid": { "2": { Bag, Effects, Traps, LastAreaId, LastBattleId } } }`），服务端只在启动时读一次。
