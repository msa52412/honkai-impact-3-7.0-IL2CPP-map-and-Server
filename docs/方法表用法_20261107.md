# 方法表用法

`rea/_rea/bh3_symtab.tsv` —— 398,316 条方法的 RVA 与签名。这是本项目最重要的一份
资产，它事实上等价于 il2cpp 的 `dump.cs`，但**比 dump.cs 多三样东西**：机器码地址、
是否静态、以及别名关系。

本文说明怎么读它、怎么查它、以及动手前必须做的三道校验。

---

## 1. 表结构

10 列，TSV，无引号，第一行是表头：

| # | 列名 | 含义 | 例 |
|---|---|---|---|
| 0 | `rva` | 相对模块基址的偏移（十六进制，无前缀） | `14A35E0` |
| 1 | `ns` | 命名空间 | `MoleMole` |
| 2 | `cls` | 类名（不带命名空间） | `GalTouchModule` |
| 3 | `method` | 方法名（构造是 `_ctor`，不是 `.ctor`） | `ChangeMainPageAvatar` |
| 4 | `ret` | 返回类型（**简写 mangle 形式**） | `bool` |
| 5 | `params` | 参数表，`类型 变量名` 逗号分隔 | `int avatarID, MoleMole.GalTouchType touchType, bool isSwitchTwins` |
| 6 | `isStatic` | 1=静态方法，0=实例方法 | `0` |
| 7 | `token` | 元数据 token | `060109BF` |
| 8 | `module` | 所属程序集 | `Assembly-CSharp.dll` |
| 9 | `aliasOf` | 非空表示**与该方法的机器码完全相同** | `UnityEngine\|Bounds\|get_center` |

规模：398,316 条，其中 Assembly-CSharp 229,018 条；`isStatic=1` 的 84,457 条；
`aliasOf` 非空的 86,934 条。

**列索引写错是常见事故**。早期代码里写 `range(8)`（`rva..token, module` 只到 8 列），
导致把 `token` 当 `module` 显示。正确是 `range(10)`，见 `rea/_rea/route.py` 第 49 行。

## 2. 五种查询方式

### 2.1 按类名精确列方法

```bash
awk -F'\t' '$3=="GalTouchModule" {print $1"\t"$4"("$6") -> "$5}' rea/_rea/bh3_symtab.tsv
```

### 2.2 按关键字模糊找（最常用）

```bash
python rea/_rea/route.py --search "MainPageAvatar"
```

输出带 RVA、完整签名、返回类型。一次最多 60 条，关键字太短就加长。

### 2.3 按方法名看完整签名

```bash
python rea/_rea/call_name.py sig "GalTouchModule::ChangeMainPageAvatar"
```

### 2.4 统计类里有哪些"看起来能用"的入口

```bash
# 找所有带 Instance 的类
awk -F'\t' '$4 ~ /[Ii]nstance$/ {print $3}' rea/_rea/bh3_symtab.tsv | sort -u

# 找所有 AvatarID 相关访问器
awk -F'\t' '{print $4"\t"$3}' rea/_rea/bh3_symtab.tsv | grep -iE "avatarid$" | sort -u
```

### 2.5 反查调用方（谁调了它）

```bash
python _analysis/callers.py who 0x14A35E0     # 谁调用 ChangeMainPageAvatar
python _analysis/callers.py calls 0x11BABD0   # ReplaceGalTouchAvatar 调了谁
```

这条路在定位「玩家点按钮时游戏走的是哪条链」时特别有效 —— 换角色那次就是靠
`who 0x14A35E0` 反查到 `NewbieDialogContext::ReplaceGalTouchAvatar`，从而确认
「对话结束弹更换按钮」的入口。

## 3. 动手前必做三道校验

### 3.1 这个 RVA 是函数入口吗

**不是入口就是死的**。跳进函数中段执行，进程会静默消失（无 dump、无 WerFault）。
本项目已经因为这个崩过一次：把 `get_forward` 的 `0x6917FF0` 记成 `0x6918300`，
后者落在 `get_right` 函数体内 +0x40。

护栏在 `icall.py`：

```python
I.is_fn_entry(rva)   # 311,382 个入口，加载 0.17s
I.fn_owner(rva)      # 返回它落在哪个函数、偏移多少
```

投递前自动检查，非入口直接拒绝；`--force` 才放行。

### 3.2 这个 RVA 是折叠桩吗

链接器会把**机器码完全相同**的方法合并成同一个地址（COMDAT folding）。此时同一个
RVA 会被多个方法名占用。

看 `aliasOf` 列最快；`route.py` 也会自动报：

```
=== BoundsInt::get_position
  别名   UnityEngine|Bounds|get_center  ← 机器码完全相同（链接器折叠）
  ⇒ 该 RVA **不能**当作「get_position」的专属入口；但它直接暴露了字段偏移
```

典型受害场景：`get_UserAvatarList` 的 RVA 与 `FileInfo::get_Name`、`AssemblyName::get_Version`
等 5 个方法相同，因为方法体都是 `mov rax,[rcx+0x60]; ret`。

**反向利用**：折叠恰恰说明它们都是「读 `this+0x60`」的字段 getter —— 这个方法直接
把字段偏移告诉你了，比查布局表还准。

### 3.3 这个方法是 IFix 热更新壳吗

本作有 13,612 个方法被 IFix 接管。它们的原函数体只剩：

```asm
mov rbx, rcx
mov ecx, <patchId>
call IFix.WrappersManagerImpl::IsPatched
test al, al
jne <patch_branch>          ← 真逻辑在这边（ILFixDynamicMethodWrapper）
<主路径>
```

判断方法：反汇编开头有 `IsPatched` 调用。`route.py` 会直接报出 patch id。

**含义**：静态反汇编**读不出真实逻辑**，别指望从壳里推断行为。
但**调用仍然有效** —— 直接 call 原 RVA，会走 patch 分支，效果和游戏内调用一致。

## 4. 类型系统：简写 mangle

符号表的类型列不是 C# 写法，也不是 `System.Int32` 写法，而是**简写 mangle**：

| 出现在 `ret`/`params` | 实际类型 | 装箱方式 |
|---|---|---|
| `void` | void | `--ret void` |
| `bool` | Boolean | `--ret int`，**只保证 `al`**，判断要 `& 0xFF` |
| `int` `uint` `byte` `short` `long` `char` | 整数族 | `--ret int` / `--arg N` |
| `float` | Single（**32 位**） | `--ret f32`；入参必须用 `I.F32(x)` |
| `double` | Double | `--ret float`；入参直接传 Python float |
| `string` | String | `--ret str`；入参用 `S("...")` |
| `object` | 任意引用 | `--ret int`（对象指针） |
| `UnityEngine_Vector3` | Vector3 | `--ret vec3`（12 字节 → sret） |
| `MoleMole.GalTouchType` | 枚举 | 按 `int` 传，**不是对象指针** |

### 怎么区分枚举和引用类型

符号表里**枚举和纯数据 struct 没有任何方法**（`GalTouchType` 作为类名 0 条），
而真类一定有一堆（`AvatarDataItem` 202 条）。`route.py` 用这个判据自动标注：

```
2. MoleMole.GalTouchType  -> int  枚举/纯数据 struct，按 32 位整数传
2. MoleMole.AvatarDataItem -> int  引用类型，传对象指针
```

### `float` 是最容易错的一个

`float 1.5` 的位模式是 `0x3FC00000`，而 `double 1.5` 的低 32 位是 `0`。
把 float 参数按 double 传，callee 读 xmm 低 32 位得到 `0.0f` —— **静默错，不报错**。
所以 `icall.py` 专门有 `I.F32` 标记，`--ret f32` 也是独立通道。

## 5. 五个坑

1. **列索引错位**。表是 10 列，写成 8 列就会把 `token` 当 `module`。
2. **`rva` 无 `0x` 前缀**，直接 `int(p[0], 16)`。
3. **构造方法叫 `_ctor`**，不是 `.ctor`；静态构造是 `_cctor`。
4. **参数带变量名**。`"int avatarID"` 要先 `split(" ", 1)[0]` 取类型；
   泛型参数 `List\`1<MoleMole.X>` 里有逗号，切分要按 `<>` 深度，不能按逗号硬切。
5. **同名不同类**。`get_position` 有几十个（`Transform`、`Arm`、`AnimationTrack`…），
   必须带类名查。`route.py` 支持 `0x<rva>` 直接查，避免歧义。

## 6. 一句话总结

> 方法表给你的是「**有哪些函数、签名是什么、机器码在哪**」，
> 不给你「**怎么调**」。怎么调要靠反汇编读实现 —— 见
> `docs/调用路线_泛化_20261107.md`。
