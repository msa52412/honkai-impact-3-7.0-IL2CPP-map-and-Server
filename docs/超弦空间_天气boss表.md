# 超弦空间 天气 / BOSS 对照表

共 **176 个配置组**，其中 140 组能凑齐 4 个场景（Area1~Area4），36 组不足 4 个。

## 怎么用

第三列那 4 个 `site_id` 就是服务端要给这一组下发的**全部**配置。它们会被一起塞进 `5203 UltraEndlessGetMainDataRsp.main_data.site_list`。

服务端的开关是 `server-v2\run\ultra_endless.json` 里的 `site_groups`（**热加载**：改文件即生效，不用重编译、不用重启）。它的元素是**组号 = `SiteID / 10`**（不是 site_id 本身）。

当前值：

```json
{ "site_groups": [165], "schedule_id": 0, "group_level": 0, "dynamic_hard_level": null }
```

即只下发 **1651, 1652, 1653, 1654** 四个站点（`1651/10 = 165`）。文件缺失或 `site_groups` 为空时，回退到代码里的 `UltraEndlessGetMainDataReqHand.DefaultSiteGroups`。

## 地图只认「第一组」，列表认全部

客户端有**两套**渲染路径，读的是同一个 `site_list`，但行为不同：

| 路径 | 方法 | 行为 |
|---|---|---|
| 地图上的 4 个 Area 槽 | `MonoUltraEndlessZoneMapCmpt.SetupSites` | 遍历 zone 节点下的 4 个 `Area1..Area4` 子节点，每个槽各调一次 `GetSiteIDByNodeName("AreaN")`，**取整个 `site_list` 里第一个匹配的站点** |
| 站点滚动列表 | `MonoUltraEndlessZoneMapCmpt.SetupScrollerSites` | 按 `site_list` 的下标逐个渲染，**全部**站点都会出现 |

`GetSiteIDByNodeName` 实物在 `0x1838640B0`：按 `site_list` 顺序遍历，`System::String::Equals(nodeName)` 命中就立即 `return`，是严格的 first-match。

如果一次下发**多个组**（例如 `[101,102,103,104]`），实际效果是：

- **地图上**的 4 个 Area 只取 `site_list` 里排最前的第 101 组 `1011/1012/1013/1014`，后 3 组的地图槽选不上
- **滚动列表里** 16 个站点全部可见

想让地图换成别的环境，`site_groups` 只写目标组号即可，例如只想用 site `1301`（组号 `130`）就写 `[130]`。

## 分组口径（实证）

分组粒度 = `SiteID / 10`，因为服务端 `ultra_endless.json` 的 `site_groups` 过滤用的就是它，而且能稳定切出「一组 4 个 Area」的结构。

- 同一个桶里即使有多个 `Area4`，**地图槽位只取表顺序最靠前的那个**
- 桶里缺 `AreaN`，那个地图节点就会被 `SetActive(false)`，少一个场景

## 数据来源

| 列 | 链路 |
|---|---|
| 天气 | `UltraEndlessSite.BuffID` → `UltraEndlessBuff`（**必须按 BuffID 取**） |
| BOSS | `UltraEndlessSite.StageID` → `StageDetail.EnemyList` → `StageDetail_Monster.BossType == 1` → `DisplayName` → `TextMap` |
| 配置id | `UltraEndlessSite.SiteID` |

> `UltraEndlessBuff.IconPath` 尾段有重名，不能拿来当天气标识：BuffID 8 / 9 都是 `QTEndless_Physics`，18 / 19 都是 `QTEndless_Meele`。
> `BuffName` 里 BuffID 5/7/11/12/13/14/15/21 全是 `WeatherEmpty`，所以只能靠 BuffID 本身区分。

## 关于 `—`（没 BOSS 的 Area）

这是表里的正常现象，不是数据缺失。按 140 个完整组统计：

| 位置 | 有 BOSS 比例 | 说明 |
|---|---|---|
| Area1 | 80% | 小怪层为主 |
| Area2 | 61% | 小怪层为主 |
| Area3 | **98%** | **几乎必有 BOSS，是关卡收尾层** |
| Area4 | 72% | BOSS 分支层 |

`—` 的含义是「这一层的 `StageDetail.EnemyList` 里没有任何 `BossType == 1` 的怪」，也就是纯小怪 / 精英层。
