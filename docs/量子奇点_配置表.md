## 判定依据：为什么单层盘卡死、多层盘不卡

第一层 BOSS 用的 wave 是**按层序固定**的，与哪张盘无关：

| 层序 | MonsterInitType | wave | MonsterGroupType | 怪物数 | HP 系数 | BOSS |
|---:|---:|---:|---:|---:|---:|---|
| L0 第一层 | 2000 | 1000 | 3 | 1 | 0.8 | BossUlysses |
| L1 第二层 | 2001 | 1001 | 3 | 1 | 0.8 | BossUlysses |
| L2 第三层 | 2301 | 1002 | 4 | 2 | 1.0 | UlyssesWarrior ×2 |
| L3 第四层 | 2401 | 1004 | 4 | 2 | 1.0 | BossUlysses + BossWendy |

关键点：**8 个单层盘不是独立内容，而是多层盘的最后一层**——

| 单层 AreaScore | 等同于 | 第一层 BOSS wave |
|---|---|---:|
| 2100 / 2101 / 2102 / 2103 | 2001 / 2002 / 2003 / 2004 的 **L3** | 1004 |
| 2104 / 2105 / 2106 / 2107 | 2005 / 2006 / 2007 / 2008 的 **L2** | 1002 |

所以「只玩第一层」时：

- **多层盘**（2001–2008，3/4 层）：第一层是 `wave 1000` 的**单只小 BOSS**，正常刷、正常打；
- **单层盘**（2100–2107、4095–4111，1 层）：第一层直接就是 `wave 1004/1002` 的**双子 BOSS**，卡死。

运行日志里卡死时的报错正好落在双怪分支：

```
LuaScriptException: QuantumEndlessCommon.lua.txt:283:
  invalid arguments to method: LevelDesignManager.StartAutoChangeLevelScoreByTime: 1215513320
  [C]: in function 'StartAutoChangeLevelScoreByTime'
  QuantumEndlessCommon.lua:283: in function 'loadMonster'
  QuantumEndless.lua:72: in function 'Func'
  LevelDesignNormal.lua:1552: in function 'do_wave'
```

`loadMonster` 被调用后第 283 行抛异常，`do_wave` 协程直接死掉 → 倒计时在走、怪不刷。
`MonsterGroupType` 3→4（单怪→双怪同场）是唯一的结构差异，
推断只有双怪分支才会调 `StartAutoChangeLevelScoreByTime`（双 BOSS 同场的追分计时），
从而撞上 lua 与 C# 的签名错位（C# 侧是 `(long initScore, float duration, long finalScore)`，相邻重载 `StartAutoChangeLevelExtraScoreByTime` 却是 `(long, long, float)`）。

> ⚠ **推论（未实测）**：多层盘不是安全，只是还没打到。
> 2001 的 L2 用 `wave 1002`、L3 用 `wave 1004`，与卡死的单层盘 2104 / 2100 完全相同，
> 所以打到第三、第四层时应当同样卡死。
