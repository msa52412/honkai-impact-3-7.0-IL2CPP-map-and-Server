# 舰桥（主界面）天气链路

> **结论先说**：舰桥/主界面展示的天气，由 proto `WarshipThemeData` 的两个字段控制：
>
> ```csharp
> [ProtoMember(4, Name = "is_weather_fixed")] public bool IsWeatherFixed
> [ProtoMember(5, Name = "weather_idx")]      public uint WeatherIdx
> ```
>
> - `IsWeatherFixed = false` → 客户端走 **Sina 实时天气 HTTP 接口**，服务端那边写死 `Condition = 1`
> - `IsWeatherFixed = true` → 用 `WeatherIdx` 指定的固定天气
>
> `WeatherIdx` **就是 1-based 的 `WeatherID`，没有 ±1 偏移**（反汇编实证，见第六节）。
> `WeatherIdx = 3` 即 `WeatherID 3 = Lightning`，也就是**雷雨**。
>
> 服务端有 **3 个下发点**，必须**同改**，否则互相覆盖（见第三节）。
> 2026-10-27 已全部改为 `IsWeatherFixed = true, WeatherIdx = 3u`，实测生效。

## 一、链路总览

```
【服务端 3 个下发点】都会产出 WarshipThemeData
    1. GetMainDataRsp.warship_theme        (ProtoMember 41)  登录 / 主数据刷新
    2. GetWarshipDataRsp.warship_lists     (5 条)            打开舰桥 / 切舰桥面板
    3. GetMainDataRsp.warship_theme        (SetWarship 回包)  切换舰桥
                    │
                    ▼
        WarshipThemeData { warship_id(1), component_list(2),
                           bgm_play_mode(3),
                           is_weather_fixed(4)  ← 开关
                           weather_idx(5)       ← 天气 ID }
                    │
        ┌───────────┴────────────┐
        │                        │
  is_weather_fixed          is_weather_fixed
      = false                  = true
        │                        │
        ▼                        ▼
  Sina 实时天气            weather_idx = WeatherID (1-based)
  GET /game_weather/             │
      weather/get_weather        ▼
  (服务端写死 Condition=1)   ThemeWeatherConfig.json
                                 │
                 ┌───────────────┴────────────────┐
                 │                                │
        AtmosphereConfigID != 0          ReplacePrefabConfigID != 0
                 │                                │
                 ▼                                ▼
        ThemeWeatherAtmosphere.json        ReplacePrefab 预制体
        Data/Rendering/
        MainMenuAtmosphereConfig/*
                 │
                 ▼
        主界面大气 / 天空盒 / 雨雪渲染
```

关键点：`IsWeatherFixed = true` 之后，`/game_weather/weather/get_weather` 这个 HTTP 接口**完全不参与**主界面天气。
那个接口只服务于「自动/实时天气」模式，改它对舰桥天气没有任何效果。

## 二、proto 定义

### 2.1 `WarshipThemeData`（`Common\Common.Resources.Proto\WarshipThemeData.cs`）

| # | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | `warship_id` | uint | 舰桥 ID |
| 2 | `component_list` | `List<WarshipComponent>` | 舰桥组件（装饰件） |
| 3 | `bgm_play_mode` | uint | BGM 播放模式 |
| **4** | **`is_weather_fixed`** | **bool** | **是否固定天气** |
| **5** | **`weather_idx`** | **uint** | **固定天气的 WeatherID（1-based）** |

> `ComponentLists` 是只读属性（`{ get; } = new List<...>()`），其余四个字段是 `Nullable<T>` 包装，
> 未赋值时 `ShouldSerializeXxx()` 返回 false → **不参与序列化**。
> 所以「只设 `WarshipId`」不会把 `IsWeatherFixed` 显式写成 false，而是让它缺省 → 客户端按 false 处理。

### 2.2 `SetWarshipSettingReq`（CmdId **5460**）

| # | 字段名 | 类型 |
|---|---|---|
| 1 | `warship_id` | uint |
| 2 | `setting_type` | `WarshipSettingType`（默认 1） |
| 3 | `bgm_play_mode` | `WarshipBgmPlayMode` |
| 4 | `is_weather_fixed` | bool |
| 5 | `weather_idx` | uint |

`WarshipSettingType`：

```csharp
[ProtoEnum(Name = "WARSHIP_SETTING_BGM_PLAY_MODE")]
WarshipSettingBgmPlayMode = 1,
[ProtoEnum(Name = "WARSHIP_SETTING_BGM_WEATHER")]
WarshipSettingBgmWeather = 2      // 改天气时 setting_type 填 2
```

### 2.3 `GetMainDataRsp.warship_theme`

`Common\Common.Resources.Proto\GetMainDataRsp.cs:466`

```csharp
[ProtoMember(41, Name = "warship_theme")]
public WarshipThemeData WarshipTheme { get; set; }
```

> 注意这是**引用类型**（`{ get; set; }`，不是 `Nullable<T>` 包装）。
> 不赋值时为 `null`，protobuf-net 会整段跳过 → 客户端保留原值，**不会被重置**。
> 这一点决定了「哪些 handler 需要改、哪些不需要」（见 3.3）。

## 三、服务端 3 个下发点（必须同改）

| # | 文件 | 下发内容 | 触发时机 | 不改的后果 |
|---|---|---|---|---|
| 1 | `Server\Handlers\GetMainDataReqHandler.cs`<br>L72-78 | `GetMainDataRsp.WarshipTheme`（ProtoMember 41） | 登录、主数据刷新 | 登录后天气就是自动模式 |
| 2 | `Server\Handlers\GetWarshipDataReqHandler.cs`<br>L16-57 | `GetWarshipDataRsp.WarshipLists`（**5 条**） | 打开舰桥、切舰桥面板 | 面板里每个舰桥显示自动天气 |
| 3 | `Server\Handlers\SetWarshipReqHandler.cs`<br>L14-20 | `GetMainDataRsp.WarshipTheme` | 切换舰桥时回包 | **切一次舰桥就变回自动天气** |

> 第 3 条最容易漏。`SetWarshipReq` 的回包里夹带了整个 `GetMainDataRsp`。
> 原来这里写的是 `WarshipTheme = new WarshipThemeData { WarshipId = ... }` ——
> **对象建了、但没带 `is_weather_fixed`**，序列化时该字段缺省 → 客户端读成 `false`
> → 切一次舰桥就变回实时天气。
>
> 反过来说：如果干脆**不设** `WarshipTheme`（保持 `null`），protobuf 会整段跳过，
> 客户端保留原值，反而不会覆盖。**「建对象但不填天气字段」比「不建对象」更危险。**

## 五、`ThemeWeatherGroupConfig`（随机天气规则，与本改动无关）

`ThemeWeatherGroupConfig.json` 6 组，供「自动天气」按组随机时使用。
当前服务端**不走**这套逻辑（`IsWeatherFixed = true` 后客户端不会去随机），仅作参考：

| WeatherGroupID | WeatherIDList | AllLevelsClearedRate | ChooseRate |
|---|---|---|---|
| 1 | 1, 2, 3 | 1, 1, 1 | 4, 4, **0** |
| 2 | 4 | 1 | 1 |
| 3 | 6, 7 | 1, 1 | 1, 1 |
| 4 | 8 | 1 | 1 |
| 5 | 9, 10 | 1 | 1 |
| 6 | 11 | 1 | 1 |

注意 Group 1 里 **WeatherID 3 的 `ChooseRate` 是 0** —— 也就是官方随机池里**永远不会**随机到雷雨。
这解释了为什么正常游戏里几乎见不到主界面雷雨，只能靠「固定天气」强开。

## 七、改成其它天气怎么做

只改**一个数字**：把三处 `WeatherIdx = 3u` 换成目标 `WeatherID`。

| 想要 | `WeatherIdx` |
|---|---|
| 晴 | `1u` |
| 多云 | `2u` |
| **雷雨**（当前） | **`3u`** |
| 雨（Hujan） | `7u` |
| 夜（Malam） | `5u` 或 `6u` |

推荐只改 1~3，因为只有这三个有完整的 `AtmosphereConfig` 实现。

## 八、实时天气分支（`IsWeatherFixed = false` 时生效）

`Server\Http\Controllers\ConfigController.cs:62-84`：

```csharp
app.Map("/game_weather/weather/get_weather", (HttpContext ctx) =>
{
    Weather weatherData = new()
    {
        Retcode = 0, Message = "OK",
        Data = new() { Timezone = 8, Hourly = new() }
    };
    Random random = new();
    for (int i = 0; i < 24; i++)
    {
        DateTime time = DateTime.Now.Add(TimeSpan.FromHours(1) * i);
        weatherData.Data.Hourly.Add(new()
        {
            Condition = 1,                        // 写死晴
            Date = time.ToString("yyyy-MM-dd"),
            Hour = time.Hour,
            Temp = random.Next(20, 30)            // 20~29℃ 随机
        });
    }
    ctx.Response.Headers.Add("Content-Type", "application/json");
    return ctx.Response.WriteAsync(JsonConvert.SerializeObject(weatherData));
});
```

**这个接口不返回雷雨**：`Condition` 恒为 `1`，`Temp` 是 20~29 的随机数。
所以「把服务端下发的天气改成雷雨」**不可能**靠改这里实现 —— 必须走 `IsWeatherFixed` 那条路。
这也是当时排查绕了一圈的原因。

客户端侧开关符号：`IsSinaWeatherOpen` @ `0x182BF0830`。

## 十、已知缺口与坑

1. **`SetWarshipSettingReq`（CmdId 5460）服务端未实现**
   `Server\Handlers` 下没有 `SetWarshipSettingReqHandler`。
   玩家在游戏内手动切天气 → 请求发上来没人处理 → 服务端不持久化。
   下次 `GetMainData` / `SetWarship` 又会被服务端强制写回 `WeatherIdx = 3`。
   **当前表现：手动改天气无效，永远回到雷雨。** 这正是本改动的预期效果；
   若以后要让玩家自选，需要补这个 handler + 把选择存进 `Player.User`。

2. **`WeatherIdx` 不持久化**
   三处 handler 都是**硬编码常量**，不是从 `Player.User` 读的。
   所以任何「按用户保存天气」的需求都要先给 `User` 加字段。

3. **三处必须同步**
   只改 `GetWarshipDataReqHandler` 会看起来「生效了一部分」—— 打开舰桥面板是对的，
   但一登录或一切舰桥就变回自动。这是最容易误判「改了没用」的坑。

4. **`WeatherIdx = 0` 不等于「无天气」**
   `0` 不是合法 `WeatherID`（表里从 1 开始）。`IsWeatherFixed = true` + `WeatherIdx = 0`
   会导致查表失败，表现不可预期。要「自动」请用 `IsWeatherFixed = false`。

5. **改 `/game_weather/weather/get_weather` 对舰桥无效**
   见第八节。这个接口只在 `IsWeatherFixed = false` 时参与。

6. **反汇编脚本的编码坑**
   `dis_va.py` 的 docstring 里有 `\_` 会触发 `SyntaxWarning: invalid escape sequence '\_'`，
   不影响执行，可忽略。
