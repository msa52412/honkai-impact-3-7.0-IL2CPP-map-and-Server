# 开放世界 · 委托界面「转圈」修复（樱色轮回 mapId=1）

> 2026-10-28 · server-v2

## 一、现象

进了樱色轮回（mapId=1）点「委托」，界面停在加载动画，转圈不结束，也不报错。

## 二、抓到的实证

服务端日志（`_launch/logs/v2_Server.log`）11:16:48 / 11:17:00 / 11:17:02：

```
11:16:48 GetOpenworldQuestActivityReq not handled!
11:17:00 GetOpenworldQuestActivityReq not handled!
11:17:02 OpenOpenworldQuestReq not handled!
```

整份日志里 `GetOpenworldQuestActivityReq` 出现 148 次，**全部** `not handled`；

`GetOpenworldSelectQuestReq` 0 次（客户端在等前面两条，根本没走到这一步）。

## 六、抽池规则

- 池 = `OpenWorldQuestData` 里 `questMap == mapId && questType == 1 && !IsActivityQuest`
- 权重 `max(1, 16 - rarity)`：rarity 1 最常见（15），rarity 15 最罕见（1）
- 同一张地图的 5 个槽不重复；候选不够时允许重复
- 槽位锁：`OpenWorldQuestSlot.UnlockStoryID` 对应剧情没打完才算锁；
  服务端没下发过这条剧情时按**已解锁**处理（否则新号 5 个槽全空）

## 八、冒险等级一直是 Lv.1（2026-10-28 补）

客户端 `NewOpenWorldModule.GetCurrentQuestLevel()`（0x183655E10）不按星数反算，直接读
`GetNewOpenworldRsp.quest_level` 的缓存（`data + 0x60`）。服务端原来写死：

```csharp
QuestLevel = 1u,
QuestStar  = 0u,
MaxQuestLevel = 30u,
```

所以面板永远是 `Lv.1 / 30`：「30」是上限配置，「1」是当前值。

另外 `TakeOpenworldQuestRewardReqHandler` 里的升级公式也是错的：

```csharp
// 旧：1 + star/10，上限 15 —— 表里是 1..30、累计 141 星满级
owQuestScheme.QuestLevel = Math.Min(15u, 1u + owQuestScheme.TotalStar / 10);
```

领一次奖就把等级算回个位数。
