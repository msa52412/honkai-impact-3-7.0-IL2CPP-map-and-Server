## 3. 怎么验的（三条独立证据）

### 3.1 与 `.pdata` 对撞

`bh3_symtab.tsv` 的 RVA 加上 0x180000000 后，去 `bh3_pdata_truth.tsv` 的函数起点集合里查：

```
全部 398,316 条  精确命中 327,884（82.3%）  剩余 70,432 条不在任何 pdata 区间（叶子函数无 unwind 信息）
Assembly-CSharp  229,018 条  精确命中 199,032（86.9%）  不在区间 29,986（13.1%）
```

一个 150 MB 的 `.text` 里有 42 万个函数，随机地址命中「某函数起点」的概率约 0.3%。
87% 不是巧合。

### 3.2 抽样反汇编：签名与函数体语义一致

| 符号 | RVA | 实测 |
|---|---|---|
| `MoleMole.LevelScoreDLCPlugin::SetActive(bool active)` | `0xD78730` | `mov byte ptr [rbx+0x38], dil` → 写 bool 字段 + 虚调用，符合 |
| `MoleMole.LevelActor::HasLevelScorePlugin()` | `0x8FEF60` | `mov rax,[rbx+0x3E8]; test; cmp byte ptr [rax+0x38],0` → 读插件指针再判激活，符合 |
| `MoleMole.LevelDesignManager::SetOWEndlessLevelScoreMode(...)` | `0x3444AA0` | 4 个形参（bool,bool,string,bool）与寄存器 `dl/r8b/r9/[rsp+0x90]` 一一对应，符合 |

### 3.3 交叉引用链自洽

`0x3444AA0` 里 `mov ecx,0xa88f; call IsPatched` → 构造 `DHJBJOLILPL::.ctor(bool,bool,string,bool)` → `NotifyManager::FireNotify(0x2F7, notify)`。
被查到的 `.ctor` 签名恰好 4 个参数、类型 `bool,bool,string,bool`，与调用点寄存器分配完全吻合 —— 表里没有错位。

## 4. 顺手修掉的 HUD 错误结论

《状态_20261106.md》里 v20 实验的结论是「`isExtra` 恒 0，面板选择不由它决定」。
现在能确认这条是**参数槽写错**导致的误判：

```
LevelDesignManager::SetOWEndlessLevelScoreMode(bool show, bool playAnim, string textmap, bool isExtra)
```

- 4 个形参，`isExtra` 是**第 4 个**（栈上传参，进函数后落在 `[rsp+0x90]` → 转存 `[rsp+0x20]` 当第 5 个实参往下传）
- 整条链是：
  `SetOWEndlessLevelScoreMode` → `new Notify{show, playAnim, textmap, isExtra}` → `NotifyManager::FireNotify(0x2F7, notify)`
  → 监听者 `InLevelMainPageContext::SetOWEndlessLevelScoreVisible(Notify ntf)` @ `0x2262070`
- 监听者内部：
  ```
  GameObject  = ctx[+0x20]                       ; 由 UI 引用缓存
  child       = GameObject.transform.FindChild(<静态字符串>)
  child.SetActive(notify[+0])                    ; = show
  ctx[+0x209] = notify[+1]                       ; = playAnim
  cmp notify[+0x10], show                        ; = isExtra 与 show 比较
  ```
  ⇒ **面板选择来自 NotifyType 0x2F7 的监听者 + 那句 `FindChild` 的静态字符串**，
  不是「第 5 个参数」也不是 prefab 结构。要切面板，改 notify 里的 `isExtra` 或直接
  在 `FireNotify` 前改写结构体，比 patch UI 稳。

> `FindChild` 的那个静态字符串在 `[rip+0x79183e1]`（RVA `0xB3A4E0`）指向的静态槽，
> 内容来自元数据字符串字面量（加密段），`global-metadata.dat` 明文区搜 `LevelScorePanel` / `ExtraLevelScorePanel` 均 0 命中。
> 11-06 的 `mem2.bin` 快照里**没有模块映像区域**（只有堆），所以也读不到这个静态。
> 要它，最省事的是下次开游戏时读一次 `base+0xB3A4E0`。

## 5. API 表（P1）正式下马

`decrypt_api_table.py` 的假设「输出 = 密文 ⊕ 密钥流」不成立。本轮把 1203 路 switch 全解出来了：

- 跳转表 `VA 0x1804D64F0`（1203 个 u32 相对偏移），分支区间 `RVA 0x466CCF..0x4D6340`
- 每个分支结构一致：
  ```
  rcx = 0x410ece9923532841 + i
  rax = rcx + 0x61c3ce6447701bcc      ; → rdx 传参
  call stub_i(&tmp, rax)              ; 每个 i 的 stub 都不同
  call 0x180432D70(&tmp)              ; 解析
  out[i] = rax + K_i                  ; K_i = 该分支里的 movabs 立即数
  ```
- `K_i` 全部提取完毕：`_ext\tmp\apitbl_branches.txt`（1203/1203）
- 拿 11-03 在进程里 dump 的 `il2cpp_api_table.txt` 做 `out−K / out+K / out^K` 三种还原：**落模块内 0/1203**，唯一值 1203 个 ⇒ 当时的解析结果不是可用的函数地址（解析依赖的运行时上下文在信箱调用里没准备好）。

⇒ 有了符号表，这张表已经没有存在意义，**P1/P2/P3 全部停做**。
