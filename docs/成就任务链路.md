## 一、客户端结构（反编译 `D:\BH3\7.0\rea\_rea\src`）

| 位置 | 含义 |
| --- | --- |
| `MonoWikiAchievementPanel`（MoleMole.cs:967787） | 成就页本体，挂在图鉴 WikiOverview 下，prefab `UI/Menus/Page/WikiOverview/WikiAchievementPanel`，入口按钮 `EntryButtons/AchievementButton` |
| `_achievementItemAllList`(+0x58) | `SetupData()` 调 `MissionModule.GetNormalAchievements()` 得到，**成就就是 Mission** |
| `_achievementItemList`(+0x50) | `FilterData()` 按左侧 AchievementTag 标签过滤后的列表 |
| `OnFetchRewardButtonClicked`(0x180F008C0) | 「领取」→ `MissionModule.RequestGetMissionReward(mission.id)` |
| `WikiOverviewPageContext`(0x1837C7A20 SetupTopPanel) | 页头 `0/340`、`0%`、进度条 |
| `MissionDataItem.get_CanFetchReward`(0x182122C70) | `status == 3(MISSION_FINISH) && 奖励列表非空` → 按钮才是「领取」 |
| `FDPCDIDPGMC.PCJGDGJKONE`(0x1820051F0) | 页头计数：遍历 `GetNormalAchievements()`，**`status == 5(MISSION_CLOSE)` 才算「已完成」** |

判定指令原文（PCJGDGJKONE）：

```
inc dword ptr [rdi+0x18]                  ; total++
cmp dword ptr [rax+0x14], 5               ; MissionDataItem.status == MISSION_CLOSE ?
jne next
inc dword ptr [rdi+0x14]                  ; done++
```

**结论：状态语义**
- `MISSION_FINISH(3)` = 条件达成、**可领取**（按钮亮）
- `MISSION_CLOSE(5)` = **已领取 / 已完成**（页头计数 +1，按钮变成「已领取」印章）

之前服务端一律发 FINISH，所以计数永远 0；点领取又没有 handler（`GetMissionRewardReq not handled!`）→ 死循环。

## 三、关键坑

1. **成就的 mission id 空间跨很多段**：50047（收集 5 个 SS 角色）、18021（用战场疾风通关 10 次）都是成就，但 6.6 表里 `thumb` 只有前者是 `SpriteOutput/AchievementIcons`，后者是 `PicMissionGen`。
   → **按 thumb 过滤会漏 25 个（315/340）**，最终改为默认「所有任务都当已关闭」。
2. 客户端认成就用的字段（AchievementTag）在 6.6 导出表里**没有**，服务端无法精确分类。
3. 领奖后不补发任务列表，客户端 UI 不会变（mission dict 只在收到 `GetMissionDataRsp` 时更新）。
4. 运行期开关 `server-v2\run\mission_ach.txt`：
   - 缺省 / `all` → 所有任务 CLOSE（成就 340/340）
   - `ach` → 只有 thumb 是成就图标的 CLOSE
   - `0` → 只有领过的 CLOSE，其余保持可领取
